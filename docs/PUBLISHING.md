# صيانة صفحة Veyora وإصدارات Windows

## الحزمة الحالية

الرابط المثبّت في HTML يشير إلى الإصدار المنشور `1.5.0`، وليس `v1.5.0`:

- ملف التشغيل المضغوط: `Veyora-Pro-1.5.0-Windows-x64.zip`.
- الحجم:302331801 بايت.
- SHA-256:`cd23cacfc15744ebf99ef92d472dde7ad08d300a915369d82481f044c713b1a9`.

هذه بيانات GitHub Releases. لم يُشغَّل هذا الملف التنفيذي في بيئة مراجعة الموقع. اختبر حزمة Windows نفسها على جهاز آخر قبل اعتماد إصدار جديد.

## نشر إصدار لاحق

1. ابنِ التطبيق واختبر التنزيل والترجمة في الاتجاهين والحفظ المطلوب على Windows.
2. اضغط مجلد التطبيق الكامل من `dist`، بما فيه `_internal`، وسمِّ الحزمة `Veyora-Pro-X.Y.Z-Windows-x64.zip`.
3. أرفقها بإصدار ثابت منشور في GitHub Releases. يدعم الموقع الوسمين `X.Y.Z` و`vX.Y.Z`.
4. اجعل الإصدار المناسب أحدث إصدار ثابت. الملفات المسودة أو التجريبية لا تُستخدم للتحميل التلقائي.
5. حدّث الرابط المثبّت والإصدار والحجم والبصمة في `index.html` و`README.md` أيضًا، حتى يبقى التنزيل صحيحًا عند تعطل API أو تعطيل JavaScript.
6. انشر التعديلات عبر فرع وطلب دمج، واختبر الصفحة على الهاتف وسطح المكتب بعد نشر GitHub Pages.

## اختيار الملف

`assets/release.js` يقبل فقط اسم حزمة التشغيل المطابق للإصدار:
`Veyora-Pro-X.Y.Z-Windows-x64.zip`.
يتحقق من أن الملف مرفق مكتمل على نفس المستودع، ولا يختار أول ZIP أو EXE عشوائيًا. إذا غيّرت طريقة تسمية الحزمة، حدّث المحدد والاختبارات معًا.

تعذر API أو عدم وجود حزمة مطابقة يبقي رابط 1.5.0 المثبّت ويعرض رسالة واضحة؛ لا يتحول الرابط تلقائيًا إلى ملفات المصدر. غياب بصمة للإصدار الجديد يخفي قسم البصمة بدل عرض بصمة الملف القديم.

## اختبارات الموقع

```sh
node --test tests/release.test.cjs

python -m http.server 8765
```

تحقق من الروابط وظهور الرسالة عند فشل API ، وجرب الصفحة بعرض هاتف، ومفاتيح Tab ، وخيارات FAQ. تحقق من أن زرالتحميل يشير لحزمةالتطبيق حتى عند تعطيل JavaScript.
