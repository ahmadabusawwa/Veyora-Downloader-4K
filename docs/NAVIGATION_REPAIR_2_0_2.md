# إصلاح التنقل وحالة المهام — 2.0.2

## الأسباب التي ثبتت من الكود

| المشكلة | السبب |
|---|---|
| Playlist يفتح تحميل الفيديو | الزر كان يستدعي `home_mode(False)`، ولم تكن هناك صفحة Playlist في موجّه الصفحات. كان اختيار القائمة متاحًا فقط بنافذة منبثقة بعد تحليل رابط. |
| إعادة الإنشاء والضغط المتكرر | `show_tab` كان يهدم أبناء `content_frame` في كل استدعاء، حتى إذا كانت الصفحة نفسها مفتوحة، ويعيد إنشاء المتغيرات والعناصر. |
| فقدان الملف والإعدادات | مسار الملف كان `StringVar` داخل دالة بناء الصفحة، دون نموذج حالة مستقل. |
| اختفاء تقدم المهمة | العامل كان يواصل العمل، لكن مستهلك التقدم والزر يشيران إلى عناصر صفحة قد هُدمت، وإلى آخر view سُجّل عالميًا. |
| callbacks وإعادة الرسم | كل إنشاء لصفحة محلية كان يضيف مؤقتًا دوريًا جديدًا؛ والتنقل يعيد تكوين القوائم والكروت. قراءة السجل وبناء جميع صفوفه كانا في UI thread. |
| التصغير والاستعادة | لم أجد ربطًا يحمّل نموذج AI عند resize. لا يمكن إثبات سبب منفصل لتعليق جهاز المستخدم من الكود وحده. أوقفت تحديث الصفحات المخفية، وجمعت تحديثات المهام في مؤقت مركزي، وأضفت اختبار 20 دورة أثناء معالجة حقيقية. |

## الحل

- `PageController`: مضيف مستقل لكل صفحة، إنشاء كسول مرة واحدة، إخفاء وإظهار، تجاهل اختيار الصفحة المفتوحة، وعزل مراجع عناصر الصفحات وكروت طابور التنزيل حتى لا تُستبدل بمراجع صفحة أخرى.
- `LocalTaskManager`: نموذج حالة مركزي مقفل، يحفظ مسار الملف واللغات وطريقة الحفظ وهوية المهمة وحالتها وتقدمها والمرحلة والوقت والنتيجة والخطأ، مستقلًا عن عناصر Tk. عامل الخلفية لا يحتفظ بعناصر Tk ولا يستدعي Tk أو `after()`.
- مؤقت واحد لتحديث مستهلكي المهام من UI thread، دون مؤقت دوري لكل صفحة. تظهر القيم المخزنة فور العودة، ولا يبدأ التنقل أي مهمة.
- Playlist حقيقية: تحليل قائمة عبر yt-dlp في الخلفية، تحديد عناصرها وإرسالها إلى الطابور. دعم الصفحات الطويلة بعرض محدود للعناصر. إصلاح روابط Generic HTML حتى لا تُرسل صفحة واحدة بدل فيديوهات القائمة المختلفة.
- السجل يُقرأ في الخلفية وتُرسم صفوفه على دفعات، مع إعادة استخدام الصفحة وتحديث بياناتها عند تغير ملف السجل فقط.
- تجنب إعادة ضبط ألوان أزرار القوائم التي لم تتغير، وإيقاف الحركة في الصفحات المخفية، وتقييد وقت تفريغ callbacks، وإلغاء مؤقت المراقبة عند الإغلاق. لا يوجد `sleep` في مسار تنقل الواجهة.
- إصلاح العناوين العربية بقي دون تغيير؛ أُجريت مقارنة AST للدالة الأصلية.

- النسخة السابقة محفوظة على `backup/veyora-2.0.1-before-navigation-fix` عند commit `4a8f02023eebb2320bbb6539a91b9f7fd694c34b`، ولم يُحذف مجلد المصدر السابق.

- لا يوجد نشر إصدار رسمي. يوجد Setup السابق أيضًا ضمن `backups/` في الحزمة الناتجة.

## الاختبارات

نتيجة أول اختبار فعلي محلي لـPlaylist والتنقل، قبل فحص Windows: تنزيل ملفين فعليين عبر HTTP وyt-dlp، و20 ضغطة على كل صفحة، و20 دورة تنقل سريعة. كل صفحة أُنشئت مرة واحدة. بقي عدد العناصر 903 والـcallbacks أربعة والخيوط أربعة؛ زاد working set بحوالي 0.31 MiB فقط في هذه العينة.

هذه النتيجة المحلية لا تُعد إثباتًا لنجاح Windows. فحص النسخة المثبّتة مضاف إلى workflow، ويجب أن ينجح قبل التسليم:

1. فتح Playlist من زرها وقراءة قائمة حقيقية وتنزيل ملفيها ومقارنة SHA256.
2. 20 ضغطة لكل صفحة و20 دورة تنقل سريع، مع قياس أعداد العناصر والـcallbacks والخيوط والذاكرة والربط العام.
3. ترجمة فعلية لفيديو بصوت مولّد محليًا مدته 180 ثانية إلى العربية، وإنتاج SRT وMP4.
4. 20 دورة تصغير وتكبير واستعادة أثناء المهمة، والتنقل والعودة والتحقق من الملف وهوية المهمة وزر الإلغاء، والضغط المتكرر على Start.
5. إلغاء مهمة فعلية بعد العودة من Downloads وSettings، بعد ظهور مقطع صوتي مفروغ فعليًا.
6. سجل محلي من عامل الكلام للتحقق أن النموذج لم يُحمّل لمجرد التنقل؛ تحميل واحد لكل مهمة فعلية، ومهمتان فقط في اختبار الإكمال ثم الإلغاء.

سيُضاف تقرير النتيجة الفعلية وروابط الملفات بعد اكتمال تشغيل Windows؛ هذا الملف يصف السبب والتنفيذ ومنهج الاختبار ولا يزعم نجاح فحص لم ينته بعد.
